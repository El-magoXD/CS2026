\begin{abstract}
Este trabajo implementa una aplicación de escritorio y una API para registrar usuarios, cifrar archivos multimedia y compartirlos. Cada archivo se cifra con una clave AES-128 aleatoria en modo GCM; RSA-OAEP protege esa clave, y la clave privada RSA se protege con AES-GCM mediante una clave derivada de la contraseña. El cliente cifra y descifra localmente, mientras que una API FastAPI almacena el contenido cifrado en SQLite durante el desarrollo o en MariaDB/MySQL para el despliegue. Esta memoria describe ambas fases, la arquitectura, los controles de acceso, el uso y las comprobaciones realizadas.
\end{abstract}

\section{Introducción}

El objetivo de la primera fase es proteger archivos multimedia con una clave simétrica aleatoria distinta para cada archivo y evitar que las claves AES almacenadas queden expuestas. Para ello se combinan algoritmos simétricos y asimétricos:

\begin{itemize}
    \item AES-128-GCM protege el contenido de cada archivo y permite detectar alteraciones.
    \item RSA-OAEP protege la clave AES aleatoria asociada a ese archivo.
    \item AES-128-GCM, con una clave derivada de la contraseña, protege la clave privada RSA.
    \item Una API HTTPS autentica las peticiones y conserva los archivos cifrados, las claves protegidas y las relaciones de compartición en una base de datos.
\end{itemize}

La aplicación está implementada en Python y cuenta con una interfaz de escritorio en Tkinter. El cliente se comunica con la API mediante HTTPS; el servidor puede usar MariaDB/MySQL y, para el desarrollo local, SQLite.

\section{Alcance del trabajo}

La aplicación trabaja sobre bytes, por lo que puede cifrar imágenes, audio, vídeo y otros tipos de archivo. El contenido se cifra en el cliente antes de enviarlo al servidor.

La aplicación permite registrar cuentas, iniciar sesión, cifrar y descifrar archivos propios, y compartirlos con otros usuarios. Cada cuenta tiene un par RSA. Al compartir, el cliente del propietario descifra localmente la clave AES y vuelve a cifrarla para la clave pública RSA del destinatario.

\section{Tecnologías y dependencias}

\begin{itemize}
    \item \textbf{Python 3.9 o posterior}: lenguaje de implementación.
    \item \textbf{PyCryptodome}: implementación de AES, RSA y generación de bytes aleatorios criptográficamente seguros.
    \item \textbf{Tkinter}: interfaz gráfica, mediante la biblioteca estándar de Python.
    \item \textbf{FastAPI y Uvicorn}: API HTTP de la aplicación y servidor ASGI.
    \item \textbf{SQLAlchemy y PyMySQL}: persistencia relacional; SQLite se usa en local y MariaDB/MySQL en el servidor.
    \item \textbf{HTTPX}: comunicación del cliente con la API.
    \item \textbf{unittest}: pruebas de autenticación, permisos, cifrado y compartición.
\end{itemize}

La interfaz gráfica también requiere que Tkinter esté instalado en el intérprete de Python. Algunas distribuciones de Linux ofrecen Tkinter como paquete del sistema separado.

\section{Arquitectura}

El proyecto se organiza en módulos para evitar mezclar la interfaz y las consultas SQL con las operaciones criptográficas:

\begin{description}[style=nextline,leftmargin=0pt]
    \item[\texttt{crypto/aes.py}]
    Genera claves AES-128 y proporciona funciones para cifrar y descifrar bytes o archivos con AES-GCM.
    \item[\texttt{crypto/rsa.py}]
    Genera un par RSA de 2048 bits y cifra o descifra claves simétricas con RSA-OAEP.
    \item[\texttt{crypto/passwords.py}]
    Deriva claves desde contraseñas con PBKDF2-HMAC-SHA256 y protege o recupera la clave privada RSA.
    \item[\texttt{api/main.py} y \texttt{api/models.py}]
    Implementan la API, sus endpoints, las sesiones y los modelos de cuentas, archivos y comparticiones.
    \item[\texttt{api/database.py}]
    Configura SQLAlchemy para SQLite local o MariaDB/MySQL mediante \texttt{CS2026\_DATABASE\_URL}.
    \item[\texttt{api/client.py}]
    Registra y autentica usuarios, cifra y descifra archivos en el cliente y vuelve a envolver claves AES para compartir.
    \item[\texttt{database/database.py} y \texttt{services/file\_service.py}]
    Conservan la persistencia SQLite de la versión local anterior; la interfaz actual usa la API.
    \item[\texttt{main.py}]
    Crea la interfaz gráfica para iniciar sesión, cifrar, descifrar y compartir archivos.
    \item[\texttt{encrypt.py} y \texttt{decrypt.py}]
    Conservan un flujo alternativo de línea de comandos que guarda el contenido cifrado como archivos externos.
\end{description}

\section{Diseño criptográfico}

\subsection{Glosario de claves y parámetros}

\begin{description}[style=nextline,leftmargin=0pt]
    \item[Clave de archivo o clave de datos ($K_F$)]
    Clave AES-128 aleatoria e independiente para cada archivo. En esta implementación, ``clave de archivo'' y ``clave de datos'' son dos nombres para la misma clave; no se genera una segunda clave por archivo.
    \item[Clave pública RSA ($(n,e)$)]
    Parte pública del par de cada usuario. Se utiliza para cifrar con RSA-OAEP la clave de archivo.
    \item[Clave privada RSA ($(n,d)$)]
    Parte secreta del par. Se almacena cifrada con AES-GCM en el servidor y se desbloquea en el cliente al iniciar sesión.
    \item[Contraseña de inicio de sesión ($P$)]
    Secreto introducido por el usuario. No se guarda en claro ni se utiliza directamente como clave AES. La API guarda un verificador scrypt; el cliente usa la contraseña como entrada de PBKDF2 para proteger exclusivamente la clave privada RSA.
    \item[Clave derivada de protección ($K_P$)]
    Clave AES-128 obtenida de la contraseña y un salt mediante PBKDF2-HMAC-SHA256. Cifra o descifra la clave privada RSA.
    \item[Salt ($s$)]
    Valor aleatorio no secreto de 16 bytes que PBKDF2 necesita para volver a derivar $K_P$.
    \item[Nonce ($N$) y etiqueta ($T$)]
    El nonce es el valor de una sola utilización requerido por GCM; la etiqueta permite comprobar autenticidad e integridad antes de aceptar el texto descifrado.
\end{description}

\subsection{Cifrado de cada archivo}

Para cada archivo nuevo, la aplicación genera una clave aleatoria de 16 bytes:

\[
16\ \text{bytes} \times 8 = 128\ \text{bits}.
\]

Esa clave se utiliza una sola vez para cifrar el contenido con AES en modo Galois/Counter (GCM). GCM produce el texto cifrado y una etiqueta de autenticación. La implementación guarda juntos el nonce, la etiqueta y el texto cifrado. Al descifrar, la etiqueta se verifica antes de escribir el contenido recuperado; si la autenticación falla, la operación produce un error.

\subsection{Protección de la clave AES}

RSA se utiliza para cifrar la clave AES, no el archivo completo. La clave pública cifra los 16 bytes de la clave AES con RSA-OAEP. Durante la recuperación, la clave privada correspondiente descifra ese material. Esta combinación permite usar el cifrado simétrico para archivos y el asimétrico para transportar la clave de cada archivo.

\subsection{Protección de la clave privada RSA}

La contraseña de la cuenta se utiliza exclusivamente para proteger y desbloquear su clave privada RSA; no cifra directamente los archivos ni sus claves AES. El cliente envía la contraseña a la API mediante HTTPS para la autenticación; el servidor almacena un verificador scrypt con salt, no la contraseña en claro. Para proteger la clave privada RSA:

\begin{enumerate}
    \item Se genera un salt aleatorio de 16 bytes.
    \item PBKDF2-HMAC-SHA256 deriva 16 bytes de clave, con 200\,000 iteraciones en la implementación actual.
    \item La clave derivada cifra la representación DER de la clave privada con AES-128-GCM.
    \item Se conserva el salt junto con el nonce, la etiqueta de autenticación y el texto cifrado de la clave privada.
\end{enumerate}

El salt no es secreto. Permite repetir la derivación durante el descifrado. Una contraseña equivocada deriva otra clave y la verificación de GCM falla. Al iniciar sesión, la clave privada se desbloquea una vez y se conserva en memoria durante esa sesión; la interfaz no vuelve a solicitar la contraseña para cada operación.

\subsection{Descripción matemática del flujo}

Sean $M$ los bytes del archivo original, $u$ el usuario, y $(n,e)$ y $(n,d)$ el par RSA de 2048 bits de dicho usuario, donde $n=pq$ y $ed\equiv 1 \pmod{\varphi(n)}$.

\paragraph{Cifrado del archivo.}
Se genera una clave de archivo uniforme mediante el generador criptográfico:
\[
K_F \xleftarrow{\text{aleatoria}} \{0,1\}^{128}.
\]
AES-GCM cifra el contenido con un nonce $N_F$:
\[
(C_F,T_F)=\operatorname{GCM.Enc}_{K_F}(N_F,M),
\]
donde $C_F$ es el texto cifrado y $T_F$ es la etiqueta de autenticación. El cliente envía al servidor $N_F\parallel T_F\parallel C_F$.

\paragraph{Cifrado de la clave de archivo.}
RSA-OAEP codifica la clave simétrica con aleatoriedad nueva. Si $\operatorname{OAEP.Enc}_{(n,e)}$ representa RSA-OAEP con la clave pública:
\[
W_F=\operatorname{OAEP.Enc}_{(n,e)}(K_F).
\]
Se almacena $W_F$ junto con el contenido cifrado. En la operación RSA subyacente, OAEP transforma el mensaje en un entero $m$ y se calcula $c=m^e\bmod n$; el relleno OAEP es parte esencial del esquema, por lo que no se aplica RSA directamente a los bytes del archivo.

\paragraph{Protección de la clave privada.}
Para la contraseña $P$, el salt $s$ y $c_{\mathrm{KDF}}=200\,000$ iteraciones:
\[
K_P=\operatorname{PBKDF2\text{-}HMAC\text{-}SHA256}
    (P,s,c_{\mathrm{KDF}},16).
\]
La clave privada serializada en formato DER se cifra con AES-128-GCM:
\[
(C_P,T_P)=\operatorname{GCM.Enc}_{K_P}(N_P,\operatorname{DER}(sk_u)).
\]
La base de datos guarda la clave privada protegida como
$s\parallel N_P\parallel T_P\parallel C_P$. No almacena $P$ ni $K_P$.

\paragraph{Inicio de sesión y descifrado del archivo.}
Al iniciar sesión, la aplicación lee $s,N_P,T_P,C_P$, deriva $K_P$ con la contraseña suministrada e intenta verificar y descifrar:
\[
\operatorname{DER}(sk_u)=
\operatorname{GCM.Dec}_{K_P}(N_P,C_P,T_P).
\]
La sesión solo se acepta si la etiqueta $T_P$ es válida y la clave recuperada corresponde a la clave pública del usuario. A continuación, RSA-OAEP recupera la clave de archivo:
\[
K_F=\operatorname{OAEP.Dec}_{(n,d)}(W_F).
\]
Por último, AES-GCM autentica y descifra el contenido:
\[
M=\operatorname{GCM.Dec}_{K_F}(N_F,C_F,T_F).
\]
La salida solo se acepta si la etiqueta $T_F$ es válida. Una contraseña incorrecta, una clave no correspondiente o una modificación del contenido producen un error de autenticación y no deben generar una salida válida.

\subsection{Compartición entre usuarios}

Sean $u$ el propietario, $v$ el destinatario y $K_F$ la clave AES del archivo. El cliente del propietario recupera $K_F$ usando su clave privada y la vuelve a cifrar con la clave pública de $v$:
\[
W_{F,v}=\operatorname{OAEP.Enc}_{(n_v,e_v)}(K_F).
\]
La API guarda $W_{F,v}$ en la relación de compartición y autoriza al destinatario a descargar el contenido cifrado. El destinatario calcula
\[
K_F=\operatorname{OAEP.Dec}_{(n_v,d_v)}(W_{F,v})
\]
y verifica y descifra el contenido con AES-GCM. El servidor no recibe $K_F$ en claro. Revocar una compartición impide accesos posteriores a través de la API, pero no elimina las copias que el destinatario ya haya descargado.

\section{Proceso de cifrado y descifrado}

\subsection{Cifrado}

Desde la interfaz gráfica, el proceso es el siguiente:

\begin{enumerate}
    \item El usuario inicia sesión con su cuenta y desbloquea su clave privada RSA una vez.
    \item Elige un archivo que se cifra con una clave AES aleatoria nueva y AES-GCM.
    \item La clave AES se cifra con RSA-OAEP y la clave pública de la cuenta activa.
    \item El cliente envía el texto cifrado y la clave AES cifrada a la API, que los almacena junto con metadatos.
\end{enumerate}

\subsection{Descifrado de un archivo propio}

Para recuperar un registro desde la biblioteca del servidor:

\begin{enumerate}
    \item Se selecciona un registro de la cuenta autenticada. Su clave privada ya está desbloqueada en memoria.
    \item RSA descifra la clave AES asociada al registro.
    \item AES-GCM descifra y autentica el contenido.
    \item Solo tras superar la autenticación, se escribe el archivo en la ubicación elegida.
    \item La interfaz pregunta si se desea abrir el archivo con la aplicación predeterminada del sistema.
\end{enumerate}

La aplicación también mantiene una pestaña para descifrar archivos externos \texttt{.enc} y \texttt{.key.enc}. La clave AES debe haberse cifrado para la clave pública de la cuenta activa. Esos archivos no se importan automáticamente al servidor.

\section{API y base de datos remota}

La interfaz no se conecta directamente a MariaDB: envía peticiones a la API FastAPI. En desarrollo, la API crea \texttt{data/server.sqlite3}; para el servidor se configura \texttt{CS2026\_DATABASE\_URL} con una URL de SQLAlchemy como \texttt{mysql+pymysql://usuario:contraseña@localhost:3306/cs2026}. Las credenciales de MariaDB solo se configuran en el host del servidor.

Las relaciones se protegen con claves foráneas. La API filtra consultas por el usuario autenticado y comprueba la propiedad del archivo o la condición de destinatario antes de entregar contenido o claves.

El contenido original y la clave AES en claro no se guardan en la base de datos. Los nombres, tamaños y fechas son metadatos legibles. MariaDB debe protegerse con permisos mínimos, copias de seguridad y acceso restringido a la red local del servidor. Los archivos se cifran íntegramente en memoria, por lo que esta versión está orientada a tamaños moderados.

Los registros de la base SQLite de la versión anterior no se migran automáticamente a la API remota.

\section{Interfaz y manual de usuario}

\subsection{Preparación}

Desde la carpeta raíz del proyecto, se crea y activa un entorno virtual.

\textbf{Linux o macOS:}
\begin{verbatim}
python3 -m venv .venv
source .venv/bin/activate
\end{verbatim}

\textbf{Windows PowerShell:}
\begin{verbatim}
py -m venv .venv
.\.venv\Scripts\Activate.ps1
\end{verbatim}

Con el entorno activado, se instalan las dependencias y se inicia primero la API local:

\begin{verbatim}
python -m pip install -r requirements.txt
uvicorn api.main:app --host 127.0.0.1 --port 8000
\end{verbatim}

En un segundo terminal se inicia la interfaz:
\begin{verbatim}
python main.py
\end{verbatim}

La API local usa SQLite. En producción, el servidor puede configurarse con MariaDB mediante \texttt{CS2026\_DATABASE\_URL}; el cliente usa \texttt{CS2026\_API\_URL} para elegir la URL HTTPS. El cliente solo acepta HTTP cuando la dirección es localhost.

\subsection{Pestaña «Cifrar»}

Al abrir la aplicación, se introduce el nombre de usuario y la contraseña. Si todavía no hay una cuenta, se puede crear una; durante el alta, el cliente genera un par RSA propio y protege la clave privada con la contraseña elegida antes de enviarla al servidor.

\begin{enumerate}
    \item Seleccionar el archivo original con el botón de exploración.
    \item Pulsar \textbf{Cifrar y guardar en servidor}.
    \item La aplicación cifra localmente y envía el resultado protegido a la API.
\end{enumerate}

El servidor recibe el contenido cifrado, la clave AES envuelta con RSA y los metadatos. No recibe el archivo original ni la clave AES en claro.

\subsection{Pestaña «Mis archivos»}

La biblioteca muestra los archivos de la cuenta activa. Se puede elegir uno para descifrar o pulsar \textbf{Compartir seleccionado}, indicar el usuario destinatario y crear una compartición. La acción \textbf{Retirar acceso} revoca la compartición indicando el nombre de usuario. La clave AES se descifra y vuelve a cifrar en el equipo del propietario.

\subsection{Pestaña «Compartidos conmigo»}

Muestra los archivos que otros usuarios han compartido con la cuenta activa. Para descifrarlos, se elige un destino; el cliente obtiene la clave AES envuelta para el destinatario y la recupera con su clave privada. Al terminar el descifrado se puede abrir el archivo con la aplicación predeterminada.

\subsection{Pestaña «Descifrar»}

Esta pestaña sirve para archivos externos. Se eligen el archivo cifrado, su clave AES cifrada \texttt{.key.enc} y la ruta de salida. Se utiliza la clave privada de la cuenta activa y no se vuelve a pedir la contraseña. Al terminar, la interfaz pregunta si se desea abrir el archivo descifrado. El modo de línea de comandos es independiente y recibe \texttt{--password} en cada ejecución.

\section{Uso desde la línea de comandos}

El modo de consola es compatible con el flujo de ficheros externos.

\textbf{Cifrar:}
\begin{verbatim}
python encrypt.py /ruta/al/archivo.jpg --password "mi-contraseña"
\end{verbatim}

Por defecto, los archivos cifrados y las claves se crean en \texttt{data/}. Se puede cambiar la ubicación de salida:

\begin{verbatim}
python encrypt.py /ruta/al/archivo.jpg \
  --password "mi-contraseña" \
  --output-dir /ruta/de/salida
\end{verbatim}

\textbf{Descifrar:}
\begin{verbatim}
python decrypt.py \
  --encrypted-file data/archivo.enc \
  --key-file data/archivo.key.enc \
  --password "mi-contraseña" \
  --output /ruta/recuperada/archivo.jpg
\end{verbatim}

Si la clave privada protegida no está junto al archivo cifrado ni en \texttt{data/}, se indica su ruta mediante la opción \texttt{--private-key}.

\section{Pruebas y comprobaciones}

La suite \texttt{tests/test\_file\_service.py} contiene pruebas automatizadas para:

\begin{itemize}
    \item Cifrar un archivo, persistir el contenido y recuperar bytes idénticos al original.
    \item Crear cuentas, desbloquear sus claves privadas y rechazar contraseñas incorrectas.
    \item Aislar los archivos de cada usuario y evitar que otra cuenta los descifre.
    \item Migrar el esquema anterior de un solo par RSA conservando los archivos cifrados.
    \item Rechazar nombres de usuario duplicados.
\end{itemize}

La suite \texttt{tests/test\_open\_file.py} comprueba que la apertura utiliza el lanzador predeterminado del sistema sin invocar una shell y que no se intenta abrir una ruta inexistente.

La suite \texttt{tests/test\_remote\_api.py} comprueba el rechazo de contraseñas incorrectas, la autenticación por token, el aislamiento de archivos por cuenta y el ciclo de compartición y descifrado por el destinatario.

\section{Seguridad, límites y trabajo futuro}

\subsection{Precauciones}

\begin{itemize}
    \item Deben conservarse la base del servidor y la contraseña para recuperar archivos; perder la contraseña o la clave privada protegida hace irrecuperables los archivos asociados.
    \item La base de datos contiene datos cifrados, pero no está cifrada íntegramente. Se recomienda restringir el acceso al servidor y realizar copias de seguridad privadas.
    \item El nombre original, el tamaño y la fecha de almacenamiento no se cifran.
    \item La contraseña viaja al endpoint de autenticación; por ello, el despliegue remoto debe usar HTTPS con un certificado válido. No debe exponerse directamente el puerto de MariaDB.
    \item La clave pública del destinatario se obtiene de la API. Esta implementación no ofrece verificación independiente de huellas digitales y confía en el servidor para distribuir las claves públicas.
    \item Revocar una compartición no puede borrar copias que el destinatario ya haya descargado o descifrado.
    \item \texttt{.gitignore} excluye datos locales y claves, pero no elimina archivos que Git ya siga ni información publicada anteriormente. Antes de compartir el repositorio debe revisarse su historial y su estado.
\end{itemize}

\subsection{Estado respecto al enunciado}

La primera y segunda fase están implementadas en el código: registro y autenticación, cifrado/descifrado por usuario, almacenamiento detrás de una API y compartición de la clave AES cifrada para el destinatario. SQLite permite probar el servidor localmente; MariaDB/MySQL está soportado para el despliegue, que requiere configurar el host, TLS y el proxy inverso.

Queda como tarea de entrega desplegar la API en el servidor definitivo y empaquetar y probar el cliente en Windows. No se afirma que el servicio ya esté desplegado en \texttt{magocloud.ddns.net}.
